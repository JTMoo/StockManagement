**Intentional addition** - today's create/edit forms sit permanently inline at the top of a list page, always rendered, fighting the search box and the table below for attention (`StockItemList`, `CustomerList`). `Dialog` replaces that: a centered `Panel`-like overlay (`surface-raised`, `radius-lg`, max 34rem wide) on a `scrim` backdrop, opened by a page's own "+ Nuevo" toolbar button or a row's "Editar" - same form either way, pre-filled for edit. `heading` title top-left, a quiet close button top-right, the form's own `form-grid` body, actions bottom-right (`Guardar` primary, `Cancelar` quiet; a create dialog also offers `Guardar y nuevo` for repeat entry).

Behavior: built on the headless kit's dialog primitive (focus trap, returns focus to whatever opened it, `Esc` and a scrim click both close it). Closing with unsaved changes needs no confirm - reopening the same "+ Nuevo" is one click, and nothing was destroyed. `Guardar` shows a `Toast` and closes the dialog; the list behind it updates in place, never a full reload. Never stack a second `Dialog` on top of one already open - a form that needs to reference another record opens the `CommandPalette` instead, over the dialog, and returns to it.
