The printed or print-preview surface for an invoice or a sale receipt - the one place this system ignores the active theme on purpose, because paper is paper: fixed light colors (`#FFFFFF` background, `#2B241C` ink, `#4A5C6A` muted, matching the light theme's own values) baked in rather than `surface-raised`/`ink`/`ink-muted`, so a receipt printed from a dark-theme session doesn't come out with reversed contrast on actual paper. `radius-sm` corners, `space-6` padding.

Header: business name left, invoice/receipt number and date right, `border-strong` rule beneath. A `dl` for RUC/customer/payment-type metadata, `small`/muted terms beside plain values. Line items as a plain table, `numeric` tabular-nums right-aligned, no header shading (no `surface-sunken` - it's meant to look like ink on paper, not an app table). The total row is the one place `heading`-sized text belongs on a receipt, `border-strong`-topped, bold. Never a `StatusBadge`, a `Dialog` or any other chrome inside it - by the time something is a `Receipt`, the transaction is done; this is a record of it, not a screen to act from.
